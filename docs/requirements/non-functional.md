## 참고

- **NFR-002의 30초와 "멈추지 않는다"는 서로 부딪힐 수 있다.** 재고 서비스가 오래 멈추면 주문마다 요청 스레드를 최대 30초 잡는다. Java 17에서는 가상 스레드를 쓸 수 없어서 요청이 조금만 몰려도 스레드가 바닥난다. 그래서 서킷 브레이커를 둔다. (OQ-009, STD-019)
- 고객 앱과 Gateway의 제한 시간은 30초보다 길어야 한다. 짧으면 주문 서비스가 아직 처리하는 중에 앞단에서 요청을 끊는다. (design 2절)
- NFR-009는 결제 서비스를 추가하는 단계에서 Saga 패턴으로 다룬다. 그 전까지는 실패한 주문의 재고를 해제 요청으로 되돌리고(OQ-002), 그래도 남는 불일치는 로그와 관리자 조회로 찾는다(OQ-003 (가)). → [ADR-0004](../adr/0004-sync-reservation-call.md)
- Pod를 늘려도 DB가 병목이면 빨라지지 않는다 (P§7 `[추론]`). NFR-005는 "주문 Pod만 따로 늘릴 수 있다"는 뜻이고, 늘리면 반드시 빨라진다는 뜻이 아니다.

## 용어

- **비기능 요구사항 (non-functional requirement)**: 기능이 무엇을 하는지가 아니라, 시스템이 장애를 얼마나 견디고 얼마나 빨라야 하는지 같은 성질을 정한 요구사항이다. 이 저장소에서는 `docs/requirements/non-functional.md`에 두고 운영 테스트 케이스로 검증한다.
- **인스턴스 (instance)**: 같은 서비스를 실행한 프로세스 하나다. 쿠버네티스에서는 Pod 하나가 인스턴스 하나다.
- **Pod**: 쿠버네티스가 컨테이너를 실행하는 가장 작은 단위다. 언제든 지워지고 새로 만들어지므로, 남아야 하는 데이터를 Pod 안에 두지 않는다.
- **롤링 업데이트 (rolling update)**: Pod를 하나씩 새 버전으로 바꿔, 서비스를 멈추지 않고 배포하는 방식이다. 바꾸는 동안 옛 버전과 새 버전이 함께 요청을 처리한다.
- **되돌리기 (rollback)**: 배포한 새 버전을 이전 버전으로 돌려놓는 일이다. 이 프로젝트에서는 `kubectl rollout undo` 명령 하나로 한다.
- **확장 (scale out)**: 같은 서비스의 Pod 수를 늘려 더 많은 요청을 처리하게 하는 일이다. 주문 서비스의 Pod 수만 따로 바꿀 수 있어야 한다.
- **자가 복구 (self-healing)**: 문제가 생긴 컨테이너를 사람이 손대지 않아도 쿠버네티스가 다시 시작하는 성질이다. liveness 프로브가 정해진 횟수만큼 실패하면 일어난다.
- **분산 추적 (distributed tracing)**: 요청 하나가 여러 서비스를 거친 경로를 한 흐름으로 이어 보는 기술이다. 추적 ID로 주문 서비스와 재고 서비스의 기록을 잇는다.
- **추적 ID (trace ID)**: 요청 하나에 붙여 여러 서비스를 따라다니게 하는 번호다. 이 번호로 여러 서비스의 로그를 한곳에서 함께 찾는다.
- **컨테이너 이미지 (container image)**: 앱과 실행에 필요한 파일을 묶어 컨테이너로 띄울 수 있게 만든 꾸러미다. 서비스마다 이미지 하나를 만들고, 환경마다 다른 값은 배포할 때 넣는다.
- **제한 시간 (timeout)**: 응답을 기다리는 최대 시간이다. 재고 호출은 시도당 2.5초, 재시도를 포함한 전체 30초를 넘기지 않는다.
- **재시도 (retry)**: 실패한 호출을 잠시 기다렸다가 다시 보내는 것이다. 이 프로젝트에서는 일시 오류에만, 최대 5번까지, 전체 30초 안에서 한다.
- **서킷 브레이커 (circuit breaker)**: 상대 서비스 호출이 계속 실패하면 한동안 호출을 멈추고 바로 실패를 돌려주는 장치다. 재고 서비스가 멈췄을 때 주문 서비스까지 멈추지 않게 막는다.
- **가상 스레드 (virtual thread)**: Java 21부터 쓸 수 있는 가벼운 스레드로, 응답을 기다리는 동안 운영체제 스레드를 잡고 있지 않는다. 이 프로젝트는 Java 17이라 쓸 수 없어서, 서킷 브레이커로 스레드가 바닥나는 것을 막는다.
- **스레드 고갈 (thread exhaustion)**: 요청을 처리할 스레드가 모두 묶여 새 요청을 받지 못하는 상태다. 재고 서비스가 오래 멈추면 주문 서비스에서 생길 수 있다.
- **게이트웨이 (gateway)**: 클러스터 밖에서 들어오는 요청을 먼저 받아 알맞은 서비스로 넘기는 입구다. 이 프로젝트에서는 Envoy Gateway가 이 일을 한다.
- **사가 (Saga)**: 여러 서비스에 걸친 처리를 서비스마다 작은 트랜잭션으로 나누고, 중간에 실패하면 앞 단계를 되돌리는 처리로 데이터를 맞추는 패턴이다. 이 프로젝트에서는 결제 서비스를 더하는 후속 단계에서 다룬다.
- **병목 (bottleneck)**: 가장 느린 한 곳이 전체 처리 속도를 묶어 두는 지점이다. Pod를 늘려도 DB가 병목이면 빨라지지 않는다.
