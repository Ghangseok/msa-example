# UC-002 주문 조회

- 상태: **확정 (2026-10-05)** (2026-10-04 초안)
- 관련: [UC-001](uc-001-place-order.md), [TC-010](../test-cases/order-placement.md), [ADR-0006](../adr/0006-keycloak-jwt-auth.md)
- 배경: OQ-002 결정에 따라 거절·실패한 주문도 기록하고 조회할 수 있어야 한다. OQ-007 결정에 따라 로그인한 사람만 조회한다.

## 1. 액터

| 액터 | 역할 | 할 수 있는 것 |
|---|---|---|
| 고객 | `CUSTOMER` | 자기 주문만 조회한다 |
| 관리자 | `ADMIN` | 모든 고객의 주문을 상태별로 조회한다. 실패한 주문과 재고 해제가 실패한 주문을 찾는 데 쓴다 |

역할은 Keycloak에서 사용자에게 붙인다. (ADR-0006)

## 2. 흐름

### 2-1. 고객이 자기 주문을 조회한다

1. 고객이 주문 목록이나 주문 번호 하나를 요청한다.
2. 시스템이 로그인한 고객의 주문만 돌려준다. 각 주문에는 주문 번호, 주문 항목(상품, 수량), 상태(처리중/확정/거절/실패), 거절·실패 사유(재고 부족이면 부족한 상품), 주문 시각이 있다.

### 2-2. 관리자가 상태별로 조회한다

1. 관리자가 상태(예: 실패)와 재고 해제 결과(예: 해제 실패)를 조건으로 주문 목록을 요청한다.
2. 시스템이 조건에 맞는 모든 고객의 주문을 돌려준다.

## 3. 업무 규칙

| ID | 규칙 | 출처 |
|---|---|---|
| BR-101 | 고객은 다른 고객의 주문을 볼 수 없다. 다른 고객의 주문 번호로 조회하면 "없음"으로 응답해, 그 주문이 있는지도 알 수 없게 한다 | OQ-007 |
| BR-102 | 관리자 조회에는 재고 해제 결과(해제 완료/해제 실패)가 함께 나온다 | OQ-002, OQ-003 |

## 4. 범위 밖

- 주문 수정, 주문 취소
- 재고 조회 (OQ-001)
- 목록의 정렬·페이지 크기 같은 세부 사항은 plan에서 정한다.

## 용어

- **유스케이스 (use case)**: 사용자가 시스템으로 목표 하나를 이루는 과정을 단계별로 적은 요구사항이다. 이 저장소에서는 `docs/requirements/`에 두고 spec.md의 출처로 쓴다.
- **액터 (actor)**: 시스템을 쓰는 사람이나 외부 시스템이 맡는 역할이다. 이 프로젝트의 액터는 고객과 관리자다.
- **역할 (role)**: 사용자에게 붙여 할 수 있는 일을 나누는 이름이다. 이 프로젝트에는 고객(`CUSTOMER`)과 관리자(`ADMIN`) 두 역할이 있다.
- **Keycloak**: 사용자 계정, 로그인, 토큰 발급을 맡는 오픈소스 인증 서버다. 이 프로젝트는 Keycloak을 직접 만들지 않고 가져다 쓰며, 계정은 초기 데이터로 넣는다.
- **업무 규칙 (business rule)**: 기술과 관계없이 업무에서 언제나 지켜야 하는 규칙이다. 유스케이스마다 번호를 붙이고 테스트로 검증한다.
- **존재를 숨기는 404 (404 to hide existence)**: 권한이 없는 대상을 "권한 없음"(403) 대신 "없음"(404)으로 응답하는 방식이다. 다른 고객의 주문 번호로 조회해도 그 주문이 있는지조차 알 수 없게 한다.
- **재고 해제 결과 (release status)**: "실패" 주문의 예약 해제가 어떻게 끝났는지 주문에 적어 두는 값이다. 해제 불필요, 해제 완료, 해제 실패 가운데 하나이고, 관리자는 이 값으로 해제가 실패한 주문을 찾는다.
- **페이징 (paging)**: 많은 결과를 정해진 개수씩 나눠 읽는 것이다. SQL에서는 `OFFSET ... ROWS FETCH NEXT ... ROWS ONLY`로 쓴다.
